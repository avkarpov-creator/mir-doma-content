# Установка локально (VS Code + Claude Code)

## 1. Клонировать репозиторий

```bash
git clone --filter=blob:none https://github.com/avkarpov-creator/mir-doma-content.git
cd mir-doma-content
```

`--filter=blob:none` не тянет картинки — экономит время и место.

## 2. Разложить файлы из этого пакета

Скопировать в корень репозитория с сохранением структуры:

```
mir-doma-content/
├── CLAUDE.md                                  ← Claude Code читает автоматически
├── CONTENT-PLAN.md
├── scripts/
│   ├── mdi.py                                 ← новый
│   ├── plugin-release.sh                      ← новый
│   └── validate.py                            ← уже есть в репо, не трогать
└── .claude/
    └── skills/
        └── mir-doma/
            ├── SKILL.md
            └── references/
                ├── article-contract.md
                ├── priorities.md
                └── plugin.md
```

```bash
chmod +x scripts/plugin-release.sh
```

## 3. Проверить

```bash
python3 scripts/mdi.py index
python3 scripts/mdi.py state
```

Ожидаемый вывод: `Статей: 117 | рубрик: 25 | сирот: 7`.

## 4. Добавить в .gitignore

```
.mdi-index.json
```

Индекс пересобирается за секунду, в репозитории ему делать нечего.

## 5. Закоммитить

```bash
git add CLAUDE.md CONTENT-PLAN.md scripts/mdi.py scripts/plugin-release.sh .claude .gitignore
git commit -m "Инструменты локальной работы: mdi.py, plugin-release.sh, скил, CLAUDE.md"
git push
```

После этого любая машина с Claude Code, клонировавшая репозиторий, получает
правила и инструменты автоматически.

## Как это работает в Claude Code

- **`CLAUDE.md`** подхватывается в каждой сессии без запроса. Там короткие
  железные правила: логирование в плагинах, `adopt_existing`, два закона экономии.
- **`.claude/skills/mir-doma/SKILL.md`** — скил проектного уровня. Claude Code
  видит его описание и активирует сам, когда речь заходит о статьях, перелинковке,
  плагинах или контент-плане. Даже на «продолжай» или «следующая статья».
- **`references/*.md`** грузятся только когда задача их требует — контракт статьи
  при написании, правила плагина при правке PHP. Это и держит расход токенов внизу.

## Шпаргалка по mdi.py

```bash
python3 scripts/mdi.py state                          # картина проекта
python3 scripts/mdi.py dupe "тема новой статьи"       # риск каннибализации
python3 scripts/mdi.py linkplan <слаг> "<Рубрика>" "<тема>"   # кто сошлётся
python3 scripts/mdi.py new <слаг> "<Рубрика>"         # скелет frontmatter
python3 scripts/mdi.py toc <слаг>                     # оглавление
python3 scripts/mdi.py sec <слаг> "Название H2"       # один раздел
python3 scripts/mdi.py in <слаг>                      # входящие ссылки
python3 scripts/mdi.py orphans                        # страницы без входящих
python3 scripts/mdi.py check [<слаг>]                 # валидация + битые слаги
```

`linkplan` для ещё не написанной статьи: слаг латиницей не с чем сопоставить,
поэтому третьим аргументом передаётся тема по-русски.

## Релиз плагина

Из корня репозитория плагина (там, где главный PHP-файл с `Version:`):

```bash
./scripts/plugin-release.sh patch "Что сделано" "Зачем"
```

Скрипт бампит версию, пишет CHANGELOG и **отказывает с кодом 2**, если в
изменённых PHP-файлах нет вызова логгера. Распознаёт `md_log`, `mir_doma_log`,
`->log(`, `error_log(`, `$this->logger` — если в плагине другой логгер, допиши
паттерн в переменную `LOGGER_RE`.
