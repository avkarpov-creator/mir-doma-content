# mir-doma.pro — правила проекта

Русскоязычный контент-сайт про дом, дачу и огород на WordPress. Метрика успеха —
рост поискового трафика. Статьи пишутся в Markdown, коммитятся в этот репозиторий,
плагин `mir-doma-git-importer` создаёт из них черновики в WordPress. Публикация —
вручную, около 3 статей в день с отложенным расписанием.

**Отвечай по-русски.**

## Первое действие в любой сессии

```bash
python3 scripts/mdi.py index && python3 scripts/mdi.py state
```

Не читай `SOSTOYANIE-PROEKTA-mir-doma.md` и старые брифы «для контекста» — данные
там устарели, актуальные есть в индексе. Подробные рецепты — в скиле `mir-doma`
(`.claude/skills/mir-doma/`), он подхватывается автоматически.

## Два закона экономии

1. **Не читай `articles/*.md` целиком.** Только `mdi.py toc <слаг>` и
   `mdi.py sec <слаг> "<H2>"` для конкретного раздела.
2. **Не выводи текст статьи в чат.** Пиши сразу в файл, в ответе — 5 строк итога.

Статья весит 15–50 КБ. Десяток статей в контексте — это обнулённое окно на
середине задачи.

## Плагины: три вещи одним коммитом

**Любое изменение PHP = бамп версии + запись в CHANGELOG (что / зачем / файлы) +
логирование в рантайме.** Не «потом допишу» — сразу. Проверяется механически:

```bash
./scripts/plugin-release.sh patch "Что сделано" "Зачем"
```

Скрипт отказывает с кодом 2, если в изменённых PHP нет вызова логгера. Обойти
нельзя — только дописать логи. Логируем вход в функцию, ветвления и результат:
на боевом сайте отладчика нет, лог — единственный способ понять, почему статья
не импортировалась или пост не ушёл в VK.

## Статьи

- `adopt_existing: true` в frontmatter при правке **любой уже опубликованной**
  статьи. Без флага импортёр молча пропустит запись — правки не появятся, ошибки
  не будет.
- `seo_title` ≤ 60 символов, `seo_description` ≤ 160.
- 6 изображений в теле и 6 в frontmatter, у каждой картинки alt.
- `category` строго из списка 27 рубрик, `status: draft`.
- **Новая рубрика или метка → сразу описание в `taxonomy/terms.md`.** Плагин
  берёт оттуда title и description для архивной страницы и Yoast; без записи
  архив выходит пустым для SEO. Пиши блок в тот же момент, когда заводишь
  рубрику или новую метку в frontmatter — не откладывай. Формат и примеры —
  в самом файле.
- Никакой смеси кириллицы и латиницы внутри слова.
- Перед добавлением внутренней ссылки слаг проверяется: `mdi.py check`, а для
  созданных вручную в WordPress записей — по живому сайту. Прецеденты были.
- Статьи, опубликованные напрямую в WordPress (без файла в `articles/`), заносятся
  в `external-slugs.txt` (слаг + комментарий, откуда взят). `mdi.py check` не
  считает такие слаги битыми и выводит их количество отдельной строкой
  «внешних ссылок: N» — так реальные битые ссылки не тонут среди ложных срабатываний.
- Полный формат — `.claude/skills/mir-doma/references/article-contract.md`.

## Перелинковка

**Страница без входящих ссылок не индексируется.** Проверено: статья про
вентиляцию погреба висела неиндексированной неделями, пока не появились ссылки.

Ссылка ставится **в теле текста в момент упоминания темы**, с объяснением зачем
переходить. Не блоком «Читайте также» в конце — глубина просмотра 1,12 это
прямо показывает.

После каждой новой статьи: `mdi.py linkplan` → правка 2–4 доноров.
Регулярно: `mdi.py orphans`.

`mir-doma-indexer` шлёт новые статьи в Яндекс и Bing через IndexNow при
публикации — это ускоряет обход, а не заменяет перелинковку. Для Google
плагин ничего не делает (только sitemap Rank Math + входящие ссылки), и на
факт индексации в целом всё ещё сильнее всего влияют именно ссылки.

## Приоритизация контента

**приоритет = кликабельность интента × близость сезонного окна × вес кластера**

Частотность запроса в формулу не входит. Квота: **2 статьи в доказанный кластер :
1 статья в тонкую рубрику** — так растёт трафик и одновременно закрываются
белые пятна. Тонкие рубрики видно в `mdi.py state`.

Статья выходит в топ за 1–3 месяца, поэтому сезонная тема пишется за 1–3 месяца
до пика спроса.

Подробно — `.claude/skills/mir-doma/references/priorities.md`,
текущий план — `CONTENT-PLAN.md`.

## Запрещено

- Выдуманные отзывы и комментарии читателей.
- Статьи под интент «как выглядит / фото / симптомы» — их целиком забирают
  AI-выжимки и карусель картинок, клики не доходят.
- Спутник, пересказывающий раздел пиллара. Прецедент: «Чем обшить веранду внутри»
  уронил пиллар с позиции 6,5 на 12,1.
- Правки родительской темы Root — только дочерняя тема.
- Класть плагины в этот репозиторий — сюда смотрит импортёр. Каждый плагин —
  свой git-репозиторий в `mir-doma-plugins/` (см. `.claude/skills/mir-doma/
  references/plugin.md`).

## Стек

WordPress + тема Root (WPShop) + Rank Math + Smush (ленивая загрузка Smush
выключена в пользу нативного `loading="lazy"`, обратно не включать — чинили CLS).
Плагины: `mir-doma-git-importer`, `mir-doma-indexer` (IndexNow для Яндекса и
Bing при публикации — Google не поддерживает IndexNow, туда не шлём и не
предлагаем Indexing API, только sitemap Rank Math), `Mir-Doma Social
Publisher` (Telegram + VK).
Данные: Яндекс.Метрика, Google Search Console, Яндекс.Вебмастер, GA4.
