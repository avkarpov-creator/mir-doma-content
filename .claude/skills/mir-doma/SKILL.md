# Мир Дома — экономный режим

Статья проекта весит 15–50 КБ ≈ 8–15k токенов. Прочитать десяток статей ради
проверки перелинковки — 100k+ токенов и обнулённое окно на середине задачи.
Скил заменяет чтение файлов запросами к индексу.

## Закон №1

**Не читай `articles/*.md` целиком. Никогда.** Всё, что обычно требует чтения,
уже умеет `scripts/mdi.py` — он читает файлы на диске и возвращает 5–20 строк.

Если кажется, что без чтения статьи не обойтись — сначала `mdi.py toc <slug>`,
потом `mdi.py sec <slug> "<название H2>"` для одного нужного раздела.

## Закон №2

**Не выводи текст статьи в чат.** Пиши сразу в файл (Write), в ответе — 5 строк:
слаг, рубрика, объём, куда встроены ссылки, что осталось на стороне пользователя.
Дублирование текста в чат удваивает стоимость статьи на ровном месте.

## Бюджет по задачам

| Задача | Разрешено читать | Запрещено |
|---|---|---|
| Новая статья | вывод `dupe` + `linkplan` (~15 строк) | статьи-соседи, брифы целиком |
| Доработка статьи | `toc` + один `sec` | весь файл |
| Перелинковка | `orphans`, `in`, `linkplan` | любые статьи |
| Контент-план | `state` + `references/priorities.md` | SEMANTIC-CORE.md целиком |
| Правка плагина | только затронутые функции (`grep -n` + `sed -n`) | весь PHP-файл |
| SEO-разбор | агрегаты из выгрузки через awk/python | сырой CSV в контекст |

## Старт сессии

Локально репозиторий уже клонирован — просто:

```bash
git pull && python3 scripts/mdi.py index && python3 scripts/mdi.py state
```

Если окружение чистое:

```bash
git clone --filter=blob:none https://github.com/avkarpov-creator/mir-doma-content.git
```

`state` даёт всю картину: количество статей, распределение по рубрикам, тонкие
рубрики, список сирот. Этого достаточно, чтобы начать. Не читай
`SOSTOYANIE-PROEKTA-mir-doma.md` и старые брифы «для контекста» — это десятки
тысяч токенов ради данных, которые устарели и уже есть в индексе.

## Рецепты

### Новая статья

```bash
python3 scripts/mdi.py dupe "тема статьи ключевыми словами"
python3 scripts/mdi.py linkplan <новый-слаг> "<Рубрика>" "<тема по-русски>"
python3 scripts/mdi.py new <слаг> "<Рубрика>"
```

1. `dupe` показал **РИСК ДУБЛЯ** → посмотри строку «Уникально в теме»: это и есть
   кандидат в дифференциатор. Либо одной фразой сформулируй, чем интенты
   различаются, либо не бери тему. Прецедент: спутник «Чем обшить веранду внутри»
   пересказал раздел пиллара — пиллар просел с 6,5 на 12,1.
2. Пиши текст сразу в файл. Формат — `references/article-contract.md`
   (читай его только когда действительно пишешь статью).
3. Расставь 3–5 ссылок в теле + правь статьи-доноры из `linkplan`, добавляя
   контекстную ссылку на новую. Без входящих ссылок страница не индексируется —
   проверено на статье про вентиляцию погреба.
4. `python3 scripts/mdi.py check <слаг>` → должно быть `OK`.

### Доработка опубликованной статьи

`adopt_existing: true` в frontmatter — иначе импортёр молча пропустит запись,
и правки не применятся. Читать только нужный раздел через `sec`, править Edit-ом.

### Перелинковка и индексация

```bash
python3 scripts/mdi.py orphans          # страницы без входящих = мёртвые для индекса
python3 scripts/mdi.py in <слаг>        # кто ссылается
python3 scripts/mdi.py linkplan <слаг>  # кто должен ссылаться, но не ссылается
python3 scripts/mdi.py check            # битые слаги по всему репозиторию
```

Перелинковка — главный рычаг, когда индекс стоит. Ссылка ставится **в теле текста
в момент упоминания темы** с объяснением зачем переходить, а не списком
«похожие статьи». Глубина просмотра 1,12 — прямое следствие ссылок блоком в конце.

### Правка плагина

Правило проекта: любое изменение = бамп версии + запись в CHANGELOG (что / зачем /
файлы) + логирование в рантайме. Скрипт делает это за один вызов и **отказывает**
с кодом 2, если в изменённом PHP нет вызова логгера:

```bash
./scripts/plugin-release.sh patch "Что сделано" "Зачем"
```

Логируй вход в функцию, ветвления и результат — иначе на сайте отладка вслепую.
Подробности и специфика плагинов — `references/plugin.md`.

### Контент-план

Читай `references/priorities.md`. Кратко: приоритет = кликабельность интента ×
близость сезонного окна × вес кластера. Частотность запроса в формулу не входит.
Квота, которая совмещает рост и покрытие: **2 статьи в доказанный кластер : 1 статья
в тонкую рубрику**. Так трафик растёт на сильных темах, но белые пятна закрываются.

### SEO-разбор выгрузок

Никогда не загружай CSV в контекст целиком. Считай агрегаты скриптом и печатай
только итог. Обязательно разделяй Google на веб и картинки: доля картиночных
показов не константа (по срезу на 30.08 — 48–65%), пересчитывай её по каждой
новой выгрузке — но искажают позиции и CTR сегменты при любом соотношении.

## Чего не делать (главные пожиратели токенов)

- `cat` / Read по статье — вместо `toc` + `sec`
- Чтение `SEMANTIC-CORE.md`, `PLAN-NEDELI-*.md`, старых брифов «чтобы вспомнить контекст»
- Вывод готовой статьи в чат вместе с записью в файл
- `git clone` без `--filter=blob:none` (тянет все картинки)
- Пересказ в ответе того, что уже напечатал скрипт
- Полный `git log` / `git diff` без `--stat` или ограничения по путям

## Файлы скила

- `scripts/mdi.py` — индекс и запросы (index, state, find, dupe, in, out, orphans, linkplan, toc, sec, check, new). Лежит в корне репозитория, в `scripts/`.
- `scripts/plugin-release.sh` — версия + CHANGELOG + контроль логирования
- `references/article-contract.md` — формат статьи и frontmatter (грузить при написании)
- `references/priorities.md` — формула приоритизации и правила контент-плана
- `references/plugin.md` — правила работы с плагинами

### Полный цикл выпуска статьи

    python3 scripts/mutagen.py pick "<фраза>" --min-freq=200 --max-strong=5
    python3 scripts/mdi.py dupe "<тема>"
    python3 scripts/mdi.py linkplan <слаг> "<Рубрика>" "<тема>"
    python3 scripts/mdi.py new <слаг> "<Рубрика>"
       написать текст, расставить ссылки, добавить входящие в 2-4 донора
    python3 scripts/images.py init <слаг>
       заполнить промпты по-английски
    ./scripts/ship.sh <слаг>

ship.sh — семь шагов с остановом на первой проблеме: токены вне git, индекс,
структура статьи, минимум 2 входящие ссылки, заполненные промпты, генерация
и проверка картинок, повторная валидация, точечный коммит только файлов статьи,
подтверждение пуша.

После пуша вручную: админка WordPress → Git Importer → «Проверить GitHub сейчас»,
ревью черновика, публикация. Автопубликации нет намеренно.

- scripts/ship.sh — полный цикл выпуска
- scripts/mutagen.py pick — отбор тем по частотности и конкуренции
- references/pipeline.md — что проверяет каждый шаг и почему

### Недельный SEO-бриф

Пользователь кладёт сводку в `seo/reports/seo-export-<дата>.md` — один файл
со всеми источниками. По фразе «сделай недельный бриф» читай
`references/weekly-brief.md` и действуй по нему.
