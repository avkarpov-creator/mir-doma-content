# Недельный бриф для владельца

## Когда

**Раз в неделю, без напоминаний.** В начале любой сессии проверь дату
последнего файла в `seo/briefs/`. Если ему 7 дней и больше, первым делом
пиши новый бриф, потом остальная работа. Владелец не должен просить.

## Откуда данные

Основной источник — API через `scripts/live.py`. Еженедельная выгрузка
`seo/reports/seo-export-*.md` больше не нужна, она используется только
как запасной вариант (см. в конце).

```bash
python3 scripts/live.py week        # неделя к неделе: трафик, Google, индекс Яндекса
python3 scripts/live.py grow 28     # позиции 5–20 — что дописать
python3 scripts/live.py ywm         # индекс Яндекса и популярные запросы
python3 scripts/live.py landing 7   # страницы входа по Метрике
git log --since="<дата прошлого брифа>" --oneline   # что сделали за неделю
```

`week` сравнивает **непересекающиеся** окна: последние 7 дней против
предыдущих 7. Для GSC окна сдвинуты на 2 дня назад, потому что данные
Google отстают. Индекс и ИКС Вебмастер отдаёт только на текущий момент,
поэтому `week` сам пишет снимок в `seo/live/snapshots.jsonl` и сравнивает
с прошлой неделей. Этот файл коммить вместе с брифом.

Для каждой статьи, которую правили 1–4 недели назад, сними
`live.py gsc-queries <слаг> 28`. Так виден эффект правки, а не только
общая динамика.

## Честность к маленьким числам

Сейчас у сайта десятки визитов в неделю, поэтому шум большой.

- Изменение меньше ~20% или меньше 10 кликов **не называй ростом или
  падением**: пиши «на уровне прошлой недели».
- Позиция по запросу с 1–3 показами — случайность, не вывод.
- Сначала проверь сезон: падение «веранды» в октябре — сезон, а не
  санкции. Сравни с тем же периодом прошлого года, если данные есть.
- Причину называй, только если она проверяема: правка статьи (дата в
  git), выпадение из индекса, апдейт поиска. Иначе пиши «причина не
  ясна, наблюдаем».

## Структура брифа

Файл `seo/briefs/<дата>.md`. Пиши для владельца: по-русски, без жаргона,
короткими фразами. Каждый пункт — что произошло и что из этого делать.

**0. Коротко.** 3–4 строки: как дела у проекта в целом, главное хорошее,
главное плохое, что предлагаю.

**1. Цифры недели.** Маленькая таблица: визиты, поиск (Google / Яндекс
отдельно), глубина, отказы, показы и клики Google (веб и картинки
отдельно), страниц в индексе Яндекса, ИКС. Колонки: эта неделя, прошлая,
изменение.

**2. Что выросло.** Страницы и запросы, которые прибавили. Почему
(наша правка? сезон?). Что сделать, чтобы закрепить.

**3. Что упало.** Страницы и запросы, которые потеряли, и выпавшие из
выдачи. Гипотеза причины и действие. Выпадение из выдачи — всегда
отдельный пункт с проверкой индексации.

**4. Что сделано за неделю и как сработало.** Новые статьи, доработки,
калькуляторы из `git log`. По тем, что вышли 1–4 недели назад, — эффект
по `gsc-queries`. Эксперименты из `seo/experiments/` с наступившей датой
замера — сюда же, с выводом «работает / не работает».

**5. Пути развития.** 2–3 варианта, куда вкладывать следующие недели.
Для каждого: что делаем, почему сейчас (данные, сезон), чего ждать и за
какой срок, риск. В конце — **моя рекомендация** одной фразой. Это
главный раздел для решений владельца.

**6. План на неделю.** Конкретные задачи по `references/priorities.md`
(квота 2:1, сезонное окно, формула). Слаги, рубрики, что дописать.

**7. Что нужно от владельца.** Только то, что я не могу сделать сам:
публикация, редиректы, доступы, деньги, решения по структуре. Пункты
из прошлых брифов, которые ещё не сделаны, переносить с пометкой
«повторно».

## После брифа

1. Закоммитить бриф и `seo/live/snapshots.jsonl`, запушить.
2. В чат — путь к файлу и 5–7 строк: главное из разделов 0, 5 и 7.
3. Продолжить работу по плану из раздела 6.

## Обязательные правила

- **GSC — веб и картинки раздельно.** Картинки дают половину показов и
  почти ноль кликов. Смешанные цифры искажают и позиции, и CTR.
- **Стоп-лист:** запросы на позиции 1–3 с нулём кликов — интент забирает
  AI-выжимка. Такие темы не берём и сниппеты не переписываем.
- **Усиливать дешевле, чем плодить спутники.** Позиции 5–20 — сначала
  дописать существующую статью.
- **Частотность в приоритет не входит.** Приоритет — формула из
  `priorities.md`.
- Глубина ниже 1,3 — проблема перелинковки, а не нехватки статей.

## Запасной вариант: ручная выгрузка

Если API недоступен, владелец кладёт `seo/reports/seo-export-<дата>.md`.
В нём каждая строка таблицы — **скользящее окно за 7 дней**, а не один
день. Соседние строки перекрываются на 6 дней из 7: их нельзя вычитать
и складывать. Сравнивать можно только срезы, отстоящие на 7 строк и
больше. Исключение — раздел «Яндекс — индексация»: это значение на
момент сбора, соседние строки сравнивать можно.
