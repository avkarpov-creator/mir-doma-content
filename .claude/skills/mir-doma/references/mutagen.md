# Мутаген: как использовать в проекте

Все данные, полученные через API, помечаются как полученные из Мутагена — это условие
лицензии на использование API (частное использование; перепродажа доступа запрещена).

## Где проходит граница

Мутаген отвечает на два вопроса:
- **есть ли спрос** — частотность Вордстата (`world_wsqso` — точная, в кавычках и скобках);
- **пробьёмся ли** — показатель конкуренции по шкале 1–25.

Он **не отвечает** на главный вопрос проекта: кликнут ли. Кластер огурцов держит позиции
1–3 и почти не даёт кликов — их забирают AI Overviews и карусель картинок. Мутаген этого
не видит, для него такой запрос выглядит выигранным.

Поэтому порядок такой: Мутаген даёт список кандидатов и отсекает неподъёмные →
формула приоритизации (кликабельность × сезонное окно × вес кластера) выбирает,
что писать. Не наоборот. Частотность остаётся вне формулы.

## Пороги

| Конкуренция | Решение |
|---|---|
| до 8 | брать сразу, шанс быстро выйти в топ |
| 9–12 | брать, если тема попадает в сильный кластер |
| 13–18 | только при закрывающемся сезонном окне и с сильной перелинковкой |
| 19+ | не брать, ресурс уйдёт впустую |

Частотность ниже 30 в месяц по точному вхождению — как правило шум, но узкий расчётный
запрос с частотностью 50 может дать больше кликов, чем диагностический с 1500.

## Команды и когда их применять

**`topics "<опорная фраза>"`** — старт работы над кластером. Отдаёт готовый короткий
список тем. Опорная фраза — ядро кластера («утепление веранды», «погреб», «сидераты»),
не длинный хвост.

**`gaps <url страницы>`** — усиление существующей статьи. Показывает ключи, по которым
ранжируются конкуренты этой страницы, а мы нет. Лучший инструмент для просевших пилларов:
вместо новой статьи-спутника (риск каннибализации) дописываем разделы в существующую.

**`watch`** — раз в неделю вместе с SEO-разбором. Упавшие и потерянные ключи. Если один
ключ виден то на одной, то на другой нашей странице — это каннибализация, лечится
разведением интентов, а не новым текстом.

**`lsi "<фраза>"`** — когда тема уже выбрана и нужно наполнить H2. Связанные фразы
показывают, что обязано быть в статье, чтобы она выглядела полной.

**`strong "<фраза>"`** — точечная проверка одной гипотезы.

**`balance`** — остаток на счету. С него стоит начинать перед массовым прогоном.

## Зависимость от индекса

Проверка дублей читает `.mdi-index.json`. Если индекс не собран, колонка «пересечение»
будет пустой и Мутаген предложит темы, которые у нас уже написаны. Порядок всегда такой:

```bash
python3 scripts/mdi.py index
python3 scripts/mutagen.py topics "<фраза>"
```

## Расходы и кэш

Проверка конкуренции тарифицируется за ключ, отчёты Мега-инструмента требуют подписки —
перед массовым прогоном сверься с `balance` и текущими тарифами на сайте.
Все ответы кэшируются в `.cache/mutagen/` и не запрашиваются повторно.
Кэш конкуренции живёт долго: показатель меняется медленно. Кэш `watch` не ведётся
намеренно — там нужен свежий срез.

Если понадобилось перезапросить фразу — удали её файл из `.cache/mutagen/`.

## Токен

`MUTAGEN_TOKEN` в окружении или файл `.mutagen.token` в корне репозитория.
Файл обязан быть в `.gitignore`: репозиторий контента публичный по смыслу пайплайна,
утечка токена = чужие расходы с твоего баланса.
