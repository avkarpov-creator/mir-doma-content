# Плагины mir-doma

## Железное правило

**Любое изменение PHP = бамп версии + запись в CHANGELOG + логирование в рантайме.**

Все три пункта — одним коммитом, не «потом допишу». Проверяется механически:

```bash
./scripts/plugin-release.sh patch "Что сделано" "Зачем"
```

Скрипт отказывает с кодом 2, если в изменённых PHP-файлах нет вызова логгера.
Обойти отказ нельзя — можно только дописать логи.

### Что логировать

- вход в функцию с ключевыми аргументами;
- каждое ветвление, которое меняет результат (нашли/не нашли пост, есть/нет
  флага, ответ API 200/ошибка);
- итог операции.

Плагины работают на боевом сайте, где нет отладчика. Лог — единственный способ
понять, почему статья не импортировалась или пост не ушёл в VK.

### Запись в CHANGELOG

Три поля, всегда: **что** сделано, **зачем**, **какие файлы** затронуты.
«Фиксы и улучшения» — не запись.

## mir-doma-git-importer

Тянет Markdown из `avkarpov-creator/mir-doma-content` (ветка `main`) и создаёт
записи в WordPress со статусом «черновик». Публикует пользователь вручную.

Известные грабли:

- **`adopt_existing: true`** — без этого флага в frontmatter импортёр молча
  пропускает уже опубликованную запись. Правки не применяются, ошибки нет.
  Самый частый источник «я же поправил, а на сайте старое».
- Таксономии берутся из `taxonomy/terms.md` — описания и title архивов
  проставляются оттуда же.
- Файлы вне `articles/` не трогаются. Поэтому `semantics/` и планы лежат
  отдельно — иначе импортёр попытается сделать из них записи.

## mir-doma-indexer

Автоматически уведомляет поисковики о новых и обновлённых статьях в момент
публикации — ручная отправка на проверку через Вебмастер/Search Console не
нужна. Исходник — `mir-doma-plugins/mir-doma-indexer/` (НЕ в этом репозитории —
здесь смотрит импортёр). Боевой: `wp-content/plugins/mir-doma-indexer/` на
mir-doma.pro. Версия на 2026-09-23 — 1.0.0.

**Каналы:**
- **Яндекс** — IndexNow (`yandex.com/indexnow`) + опционально переобход через
  API Яндекс.Вебмастера v4.
- **Bing и другие участники IndexNow** — через `api.indexnow.org/indexnow`.
- **Google — НЕТ, и это осознанно.** Google не поддерживает IndexNow, пинг
  sitemap отключён, а Indexing API официально разрешён только для
  вакансий/трансляций — использовать его для обычных статей запрещено
  (риск для сайта). Для Google работают sitemap Yoast и входящие
  внутренние ссылки — то есть перелинковка из CLAUDE.md никуда не делась,
  индексатор её не заменяет. **Не предлагать «подключить Google Indexing
  API для статей»** — это прямо запрещённый вариант, не просто неприоритетный.

**Триггеры:** `transition_post_status → publish`. Новая публикация (в т.ч.
отложенная и через импорт из GitHub) — IndexNow + переобход Вебмастера.
Повторная публикация уже опубликованной записи (`publish → publish`, в т.ч.
`adopt_existing`) — только IndexNow, не чаще раза в час на URL. Ревизии,
автосохранения, записи под паролем и закрытые `noindex` пропускаются. С v1.0.1
noindex берётся из Yoast (`_yoast_wpseo_meta-robots-noindex` = '1', при пустом —
настройка типа записи `wpseo_titles['noindex-<тип>']`), Rank Math — запасной.
До v1.0.1 проверялся только Rank Math, и на сайте с Yoast она не срабатывала.

**Известные грабли:**
- **Не включать параллельно другие IndexNow-плагины** (IndexNow от Microsoft,
  Instant Indexing и т.п.) — даст двойную отправку в одни и те же каналы.
- Токен Вебмастера (OAuth) **никогда не попадает в лог, терминал, чат или
  коммит** — если правишь этот плагин, следи, чтобы дебаг-логирование его не
  зацепило.
- IndexNow-ключ отдаётся файлом `/<ключ>.txt` через PHP-хук `init`, физически
  в корне сайта не лежит — если файл отдаёт 404, значит кэш или nginx
  перехватывает `.txt` раньше WordPress, нужно добавлять исключение в кэш.
- Работает через WP-cron (очередь `mdin_queue` + `wp_schedule_single_event`);
  при `DISABLE_WP_CRON` нужен системный cron на `wp-cron.php`, иначе очередь
  копится и не разбирается.
- Ошибки 403/429/5xx/сеть повторяются почасовым cron (`mdin_hourly`), максимум
  6 попыток, дальше `failed` + запись в лог. Квота Вебмастера (429
  `QUOTA_EXCEEDED`) не сбрасывает счётчик попыток — просто ждёт следующего дня.

**Проверить, что работает:** опубликовать статью → через 1–2 минуты в логе
плагина (Инструменты → «Индексация (Мир Дома)») должны появиться «IndexNow:
принято» по обоим эндпоинтам и, если включён Вебмастер, «Вебмастер: заявка
принята» с `task_id`. Очередь после этого должна быть пустой.

## Mir-Doma Social Publisher

Автопостинг в Telegram и VK при публикации, плюс массовая отправка старых статей.

- **VK: ссылку на статью класть в текст сообщения, не в `attachments`.**
  Параметр `attachments` валидирует размер `og:image` и отклоняет пост целиком,
  если картинка не проходит по правилу. Диагностировано и исправлено в 1.0.1.
- Telegram менее придирчив, но превью тоже зависит от `og:image`.

## Mir-Doma Cookie Consent

Согласие на cookie по 152-ФЗ. Исходник — `mir-doma-plugins/mir-doma-cookie-consent/`
(основа — Nordic Cookie Consent 1.1.2, префиксы `ncc_` оставлены как в исходнике), zip
`mir-doma-cookie-consent-<версия>.zip` рядом с папкой `Git`. Подробно — его README.

- **Метрику подключает плагин** после согласия; ID и Вебвизор — «Настройки → Cookie (152-ФЗ)».
  В HTML нет `mc.yandex.ru` до согласия — это норма, а не пропавший счётчик. Любой другой
  код Метрики (поля кодов темы Root `code_head` / `code_body` / `footer_counters`, плагины)
  должен быть удалён, иначе грузится без согласия. Google Analytics не подключается вовсе
  (решение владельца 2026-10-19: GA4 убрать, GSC оставить).
- Цели калькуляторов `ym(..., 'reachGoal', ...)` до согласия копятся в очереди — не ломаются.
- Комментарии: обязательная галочка согласия (мета `_ncc_consent`), Gravatar заменён заглушкой.
- После смены настроек версия согласия растёт — **сбросить кеш страниц**.
- Подвал Root: ссылки дописываются в `footer_text` опции `root_options` на время вывода подвала.
- Тестировать локально: тема Root без лицензии обрывает страницу после `<body>` — для
  проверки подвала нужен макет темы со слагом `root` (так делали 2026-10-19), а не обход лицензии.
- Google Fonts темы Root (`google-fonts`, fonts.googleapis.com) плагин **не** убирает — это
  отдельная задача в дочерней теме.

## Версионирование

Каждый плагин — свой git-репозиторий внутри `mir-doma-plugins/` (например
`mir-doma-plugins/mir-doma-git-importer/`, `mir-doma-plugins/mir-doma-indexer/`),
рядом с папкой своего главного PHP-файла с заголовком `Version:` — не единый
репозиторий на все плагины сразу. Класть плагины в этот (content) репозиторий
нельзя, туда смотрит импортёр. Релиз каждого плагина собирается в zip и
устанавливается на сайт вручную пользователем — автообновления нет.

## Тема сайта

Root от WPShop, правки только через дочернюю тему — родительскую менять нельзя.
Файлы `theme/custom.css` и `theme/custom.js` в репозитории контента.
Ленивая загрузка Smush выключена в пользу нативного `loading="lazy"` — это
чинило CLS, обратно не включать.
