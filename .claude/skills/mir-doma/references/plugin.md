# Плагины mir-doma

## Железное правило

**Любое изменение PHP = бамп версии + запись в CHANGELOG + логирование в рантайме.**

Все три пункта — одним коммитом, не «потом допишу». Проверяется механически:

```bash
./scripts/plugin-release.sh patch "Что сделано" "Зачем"
```

Скрипт отказывает с кодом 2, если в изменённых PHP-файлах нет вызова логгера.
Обойти отказ нельзя — можно только дописать логи.

### Что логировать

- вход в функцию с ключевыми аргументами;
- каждое ветвление, которое меняет результат (нашли/не нашли пост, есть/нет
  флага, ответ API 200/ошибка);
- итог операции.

Плагины работают на боевом сайте, где нет отладчика. Лог — единственный способ
понять, почему статья не импортировалась или пост не ушёл в VK.

### Запись в CHANGELOG

Три поля, всегда: **что** сделано, **зачем**, **какие файлы** затронуты.
«Фиксы и улучшения» — не запись.

## mir-doma-git-importer

Тянет Markdown из `avkarpov-creator/mir-doma-content` (ветка `main`) и создаёт
записи в WordPress со статусом «черновик». Публикует пользователь вручную.

Известные грабли:

- **`adopt_existing: true`** — без этого флага в frontmatter импортёр молча
  пропускает уже опубликованную запись. Правки не применяются, ошибки нет.
  Самый частый источник «я же поправил, а на сайте старое».
- Таксономии берутся из `taxonomy/terms.md` — описания и title архивов
  проставляются оттуда же.
- Файлы вне `articles/` не трогаются. Поэтому `semantics/` и планы лежат
  отдельно — иначе импортёр попытается сделать из них записи.

## Mir-Doma Social Publisher

Автопостинг в Telegram и VK при публикации, плюс массовая отправка старых статей.

- **VK: ссылку на статью класть в текст сообщения, не в `attachments`.**
  Параметр `attachments` валидирует размер `og:image` и отклоняет пост целиком,
  если картинка не проходит по правилу. Диагностировано и исправлено в 1.0.1.
- Telegram менее придирчив, но превью тоже зависит от `og:image`.

## Версионирование

Плагины пока живут только как zip-архивы на сайте. Нужен отдельный репозиторий
`mir-doma-plugins` — класть их в репозиторий контента нельзя, туда смотрит
импортёр.

## Тема сайта

Root от WPShop, правки только через дочернюю тему — родительскую менять нельзя.
Файлы `theme/custom.css` и `theme/custom.js` в репозитории контента.
Ленивая загрузка Smush выключена в пользу нативного `loading="lazy"` — это
чинило CLS, обратно не включать.
